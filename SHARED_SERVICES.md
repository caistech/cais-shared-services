# Shared Services Catalog — what's available to consume (read before building)

> **Purpose.** This is the portfolio's **single capability index of the `@caistech/*` shared
> substrate.** Read it before building anything non-trivial, so you *consume* an existing shared
> service instead of re-forking one (the `@caistech`-first rule + the fork-check guard exist
> precisely to stop the second person rebuilding what the first already extracted). If a capability
> below covers your need, install and consume it — do not hand-roll a local copy.
>
> **It is auto-loaded every session** (imported by the global CLAUDE.md, the same mechanism that
> loads `BUSINESS_MODEL.md` + `PRODUCT_STANDARDS.md`), so every agent in any repo starts knowing
> what the substrate already offers.
>
> **Maintenance rule (non-negotiable).** When you **add a new `@caistech/*` package** or **extend an
> existing one with a notable capability**, update this catalog in the SAME change — a shared service
> that isn't listed here is invisible to every future session and *will* get re-forked. Keep entries
> one-line and capability-focused. Source of truth for each line is the package's own
> `package.json` description; regenerate the bulk of this file from those descriptions if it drifts.
>
> **Standing rule — convergent shape, then extract (the "build-alike" rule) [non-negotiable].** When
> you build a capability a SIBLING product already has and **no `@caistech/*` package exists yet**,
> build the new one to the **SAME SHAPE** as the existing implementation — mirror its exported types,
> field names, function signatures, and UX — rather than a divergent design. The **2nd occurrence is
> the extraction trigger** (`BUSINESS_MODEL.md` §6); this rule is its *precondition*: convergent
> implementations make the eventual `@caistech` extraction a **lift**, divergent ones force a
> **rewrite** and quietly defeat the extraction detector + the fork-check. Applies to engines, data
> shapes, **and UI components** (e.g. a product's cost dashboard mirrors the cockpit's
> `UsageAnalytics` shape so the two can later collapse into ONE shared component). Consume-first (the
> `@caistech`-first rule) still wins whenever the package already exists; this governs the case where
> it does **not** yet — build it *alignable*, so bringing it in as canonical is mechanical.
>
> **Install:** registry is GitHub Packages (`@caistech:registry=https://npm.pkg.github.com`, token
> `NODE_AUTH_TOKEN`/`GITHUB_PACKAGES_TOKEN`). `npm install @caistech/<name>`. Consumers import the
> compiled `dist/`, never source. **Last updated:** 2026-08-13 (53 packages).
>
> **OPEN EXTRACTION CANDIDATES — second occurrence reached, package not yet built.** Listed here so a
> third implementation is a deliberate choice rather than an accident:
> - **`@caistech/google-workspace`** (Drive + Gmail + Contacts over one OAuth client). Two live
>   implementations: **F2K-Checkpoint** `src/lib/drive/client.ts` (single identity, one script-minted
>   refresh token in env — right for one company's own mailbox) and **orchestrator**
>   `src/connectors/google.ts` (multi-tenant, per-owner consent, tokens in `connections`). Checkpoint's
>   is the more mature client; the orchestrator's is the correct tenancy model. Setup shape, scope set
>   and the silent-failure traps are canonical in **`GOOGLE_WORKSPACE_CONNECTOR.md`** — read it before
>   writing any Google integration.
> - **Conversational, effect-asserted red-teaming** → belongs INSIDE
>   `@caistech/security-gate/red-team`, which already exists and which **Kira did not consume** (it
>   built `scripts/red-team.mjs` + `lib/kira/redteam.test.ts` + its own tables instead — an
>   `@caistech`-first miss the fork-check did not catch). They are not duplicates: security-gate's
>   `Probe` is **single-turn** and scores the **response text** with `failureIndicators: RegExp[]`,
>   while Kira's is **multi-turn** and takes its verdict from **observed side-effects** (DB state
>   before/after). *Does this endpoint say something it shouldn't* vs *can this agent be talked into
>   doing something it shouldn't* — and for an agent holding a real person's Drive, contacts and mail
>   the second is the one that matters, because an agent that says the right thing and does the wrong
>   one passes a regex and fails the customer. **Full directive:
>   `packages/security-gate/RED_TEAM_CANONICAL.md`** — adds `ConversationProbe`, a transport seam, a
>   non-negotiable synthetic-subject contract (Kira's first run pointed at the LIVE owner's account
>   and was saved by an unrelated 403), and pass-RATE-over-time instead of `regression: boolean`,
>   because these suites are non-deterministic. ⚠️ Two live consumers (SayFix, platform-trust) — the
>   no-orphaned-consumers rule applies to every type change.
> - **Document text extraction** (PDF/docx/xlsx → text). Belongs in `@caistech/dataroom-core`'s
>   already-documented-but-unshipped `/ingest` subpath, NOT forked per product.
>   `@caistech/document-ingest` is not it — that one is specialised to AU subdivision approvals.

Born from a real month-long silent outage: every ExecutorAI production deploy failed at `npm install` (expired `NODE_AUTH_TOKEN` → 401 from GitHub Packages) while prod served a month-old build; the undeployed commits included RLS column-exposure hardening and admin MFA enforcement — security work already described to a partner as remediated. **Deliberately stricter skip policy than the memory-loop gate:** "no voice agent" is a real detectable non-applicability, but *every product deploys*, so missing config **FAILS**; a genuinely non-Vercel repo opts out with a **recorded reason** (`--not-applicable "<reason>"`; a bare opt-out is rejected). Config resolves CLI flag → env → `.vercel/project.json`; `--wait` polls until a push's build settles. Wired into `templates/.github/workflows/gate.yml` on push/schedule (not PRs — it judges *production*), with the same loud `::warning` on an older installed version. **v0.10.0 adds `portfolio-gate-audit-machine-routes`** — *does the middleware matcher silently swallow the routes MACHINES call?* A session-refresh middleware redirects anything without a session, and a Next matcher normally runs on everything, so a vendor webhook or cron route is **307'd to /login unless explicitly excluded** — and a redirect is not an error, so nothing throws, nothing logs, the caller often follows it to a 200 HTML page, and the feature simply never runs. **ExecutorAI lost the same feature to this twice in one day**: every ElevenLabs call to its convai webhooks (no voice memory was ever written or read), then every scheduled retention purge. Both looked healthy from outside. The cause is structural rather than careless — the exclusion lives in a regex in `middleware.ts`, far from the route that depends on it — so the check moves the requirement **onto the route**: mark it `@machine-callable` and the audit fails if the matcher still captures it. **Scope is deliberately narrow and stated:** it only checks *marked* routes, because "is this called by a browser?" is not statically decidable; the marker is still something a person must remember, but it is small, local, and in the file they are already editing. **SKIPS (not fails) with no middleware or no marked routes** — both are genuine non-applicability, unlike a missing config — and **warns rather than passing** when the matcher cannot be parsed, refusing to report a verdict it did not establish. Verified by reintroducing the real bug: removing one exclusion flipped it to exit 1 naming the exact route, restoring it returned exit 0. Wired into `templates/.github/workflows/gate.yml`. **v0.11.0 adds `portfolio-gate-audit-public-routes` — the BROWSER-facing twin: can a visitor with no session actually open the pages we publish?** Machine-routes covers webhooks and crons; the identical structural failure hits **public marketing pages**, and it is worse there because it is customer-visible. ExecutorAI shipped `/for-advisers` without adding it to the middleware's public allowlist, so every visitor was 307'd to `/login` — and **the entire verification stack went green over it**: `curl -L` *followed* the redirect and returned **200**; the deploy gate's `--app-marker` assertion *matched*, because the login page carries the product name too; and `deploy-status` *passed*, correctly, since production genuinely was serving the expected SHA. Status-code checks, marker checks and deploy-SHA checks can therefore all pass over a page nobody can open. **`redirect: 'manual'` is the whole check** — following the redirect is precisely what hides the bug. Mark a page `@public-route`; the audit probes each without following redirects, FAILS on a 3xx (naming the status *and* the Location, since "307 → /login" is the diagnosis and "307" alone is not), and **warns** on a 200 whose body contains a `type="password"` input — the sharp signal for a component-level gate, chosen over matching the words "sign in" because a marketing page routinely *links* to sign-in but should never *contain* a password field, and because a repo may legitimately mark its own `/login` public. Deliberately does NOT use `probeOnce`: that returns `{status}` only by design, and a useful failure here needs the Location header — so it follows `smoke/auth.ts`'s in-package precedent of raw fetch with manual redirect rather than forking the shared transport or widening its contract. SKIPS with no marked routes; **FAILS when routes are marked but no base URL is configured** (`--base-url` → `PORTFOLIO_GATE_PREVIEW_URL` → `PUBLIC_ALIAS`), because an unverified public page is the bug itself. Verified the same way as machine-routes — against ExecutorAI production it passed on the fixed tree, then falsely marking the gated `/dashboard` flipped it to exit 1 with `307 → /login`. In `gate.yml` it is ordered **after** `deploy-status --wait`, so on push it probes the deployment for *this* commit rather than the previous one. **v0.9.0 makes the memory-loop gate usable and honest:** it now **auto-discovers `./memory-loop.config.json`** (previously read only with `--config`, so a bare `--base-url` run bypassed a repo's recorded `memoryLoop:false` opt-out and probed a product that had already declared there was nothing there — SayFix, three times), **prints the resolved target** (URL, identity mode, uid, post-call URL) on every run because three runs were once spent diagnosing a red caused by a misnamed variable pointing at an empty string, surfaces the options the probe gained in convai 0.11.0 (`identityMode`/`conversationId`/`agentId`/`postCallUrl`/`expectDistil`/table-name overrides — `postCallUrl` had been unreachable through the gate, i.e. the check with the most direct security consequence was the one that could not be configured), and renders **`SKIP` at the same weight as `FAIL`**, excluded from the verdict rather than counted green. **v0.12.0 adds `portfolio-gate-audit-first-paint` — does the page a visitor lands on actually SAY anything before the JavaScript arrives?** The sibling question to `public-routes`: that one asks whether a visitor can REACH the page, this asks whether reaching it shows them anything. Kira served three pages behind its three main CTAs as a header, a footer and **sixteen characters** — the SayFix widget's "Report a problem" — while a tester timed 15s of white on the one that asks for a card: *"not a slow page, a broken one, and I have no way to tell the difference."* **Every reachability signal was green and correct**: 200, expected commit, no redirect, so `deploy-status`, `smoke-routes` and `public-routes` all passed over it. **The obvious implementation is the wrong one, and this is the whole design:** those pages were not empty documents — they served full chrome — so "does the response contain visible text" PASSES on the exact defect it was written for (`/plan` scores 180). It therefore measures visible text **outside `<header>`/`<footer>`/`<nav>`**, via a depth-counting scanner rather than a regex, because chrome nests and a non-greedy `<header>.*?</header>` silently under-counts it, reintroducing that false negative. **Passes on enough text OR a real heading** (`≥8` chars, first `h1`/`h2`/`h3` outside chrome) — a sign-in page is legitimately sparse, and a bare character threshold pressures whoever fixes it into padding the page with copy written to satisfy an assertion, which is worse than the defect; *having no way to tell where you are* is the failure, sparseness is not. **No browser needed** (the defect is in the server response, so `fetch` sees exactly what the visitor sees in second one) and it reuses the existing `@public-route` marker rather than inventing a second one nobody remembers. Reachability stays `public-routes`' verdict — a non-200 is skipped here rather than double-counted. First run found a **fourth** blank page no tester had ever seen (`/signup` — the persona would not create an account) and **disproved** the recorded diagnosis for a fifth (`/genome` already server-renders 3,935 chars; the planned "move `'use client'` down" would have changed nothing and been reported as a fix). **v0.15.0 adds two checks for the class of failure where nothing is broken and everything is wrong.** (1) **`portfolio-gate-audit-flag-coherence` — is the live site entirely in ONE mode, or half-flipped?** MMC Build opened for business by setting one variable; **eight surfaces switched and two did not**, because they had never been wired to the flag — including the homepage hero, still offering a waitlist and pointing at `/contact` on a site that had started selling. Every existing signal was green *and correct*: build passed, flag set in both projects, 200 on all thirteen pages, so `deploy-status`, `public-routes` and `first-paint` would each have passed over it. **A feature flag can only switch the surfaces somebody remembered to attach to it, and there is no error for the one they forgot.** Two decisions carry the check and the obvious implementation gets both wrong: it **DETECTS the active mode rather than being told it** (a config saying "should be in purchase mode" must be edited at flip time — the moment nobody wants to stop and update a test — and is silent about a ROLLBACK stranding purchase copy, which matters because flipping back is usually a product's fastest rollback); and it matches the **shortest distinguishing token, never a phrase** — the trap that hid the original bug for an hour from the person looking straight at it, since a grep for `join waitlist` returned **zero** while "Join THE Waitlist" sat in the hero. A **stale config FAILS** (no marker matching anywhere means the check has quietly stopped guarding anything, and an assertion that no longer matches reality reads as green forever); a **tie reports AMBIGUOUS** rather than guessing, because a site showing two modes at once is the defect itself. Raw HTML is searched, not rendered text — it over-counts and never under-counts, the safe direction for a check whose job is proving ABSENCE. SKIPS with no `flag-coherence.config.json`. (2) **`portfolio-gate-audit-social-proof` — is every testimonial, partner logo and headline metric one a human attested to?** A REGULATED-tier client's live site carried **eight real, named ASX-listed builders as "Trusted Partners"** (none were partners), three invented testimonials, and "100+ professionals / $2M saved" — scaffold filler public for months because nobody read it again once real copy went in around it. **Nothing in the portfolio looked for this**, so the same filler may sit in any scaffolded repo. ⚠️ **The check does NOT judge truth** — a real and an invented testimonial are both a string with a name on it, and a check that tried would either flag every genuine one (and be switched off in a week) or catch nothing. It asserts two things instead: **known scaffold filler is always wrong** (ships in the template or was found live — no opt-out, not silenceable by attestation, since a template string cannot become true because somebody signed for it), and a **social-proof SURFACE must carry `// @social-proof-ok: <who confirmed it, when>`** — the same "silence is not acceptance" shape as `REGULATORY_INCLUSIONS`. One line, once, for a genuine section; the point is not cleverness but making the **absence of a human decision visible**, because the actual MMC failure was that nobody had ever decided those names should be there. First run against the real marketing repo: **9 findings**, including a surviving `"what our customers say"` heading in a component still rendered on the homepage (correctly emptied and gated on 5 Aug — but with nothing in the file recording *why*, which is exactly the missing attestation). 21 tests. ⚠️ **`tax-suffix` already existed and must not be re-forked** — it was nearly rebuilt during this promotion. **v0.16.0 adds `portfolio-gate-audit-sibling-parity` — things that must be true in MORE THAN ONE PLACE at once.** Every other audit here interrogates ONE deployment; this one interrogates the RELATIONSHIP between two, which is where a whole class of silent failure lives. Three incidents in one week were the same structural fact: a flag switched **eight surfaces and not the ninth**; a Stripe tax registration was set in **one mode and not the other**; web analytics was toggled on for **two projects and one repo had no analytics component** — toggle on, dashboard agreeing, and the site with nothing to send. None were carelessness: **a setting and the code it depends on lived in different places, and only one was visible from where the person was standing.** Asserts three things, each mechanical: `identicalFiles` (a by-design-identical file across siblings really is — MMC's `purchase-cta.ts` was verified by hand with `diff`, which works exactly once, and the two pricing pages had already drifted before anyone noticed), `sharedDependencies` (present in every sibling that needs it — the analytics incident exactly; **silent when NEITHER has it**, since that is a choice rather than a drift and the audit must not claim to know which features a product ought to have), and `parityPaths` (a URL answering the SAME status on every sibling site). ⚠️ **Partial runs are REPORTED, never silently passed** — in CI usually only one sibling repo is checked out, so file/dependency comparison SKIPs with a warning while the live checks still run; a comparison that quietly compared one thing to itself would pass forever. ⚠️ **A FAILED FETCH IS NOT A STATUS** — the first real run against the MMC pair returned `app=0, marketing=200` from a transient network blip and reported two identically-configured sites as a parity defect. Now: one retry, then **unreachable ⇒ inconclusive (warn), never a difference** — *not knowing is not the same as knowing they differ*, and a check that cries wolf gets switched off. Its bin uses `process.exitCode` rather than `process.exit()`, which aborts with a libuv assertion while fetch handles close and exits **127** ("crashed") where **1** ("found a problem") was meant. 11 tests. **v0.17.0 adds `portfolio-gate-audit-offer-claims` — does the page state a price and a free-trial length the product actually charges and grants?** Every other check here asks *"did a change break something?"*; this asks the opposite, and the inversion IS the design: **text that has sat unchanged for months while the truth moved underneath it never appears in a diff**, so review after review walks straight past it. One MMC pricing page carried, at the same time, a FAQ promising "the Essential plan free for 1 month", a plan badge promising "free for 1 month", a CTA claiming "card required at sign-up" four inches from a signup page reading "No credit card required", and an assistant reporting a "60-day free trial" — against a real offer of 14 days, no card, every plan. Two had been live for months, on a site taking payment. **The config declares the truth and STRIPE VERIFIES THE CONFIG** (`verifyAgainstStripe`): without that the check merely relocates the lie into a second file nobody re-reads and goes green forever once THAT goes stale, so a declared price disagreeing with the live Price object FAILS, and a requested verification with no key FAILS rather than skipping. **Comments are excluded from the scan** — earned from the sibling social-proof check, where an honest note recording a removed filler string quoted it and failed on its own explanation; punishing that teaches people to delete the explanation instead. **A money figure needs selling language within ±2 lines** (`price`/`plan`/`/mo`/`billed`…): the first real run flagged "$485,000" vs "$445,000", an illustration of a saving on a BUILD rather than anything the product charges, and a check that cries wolf on every dollar sign in the marketing copy is switched off within a week and then protects nothing. Catches **word-form durations** ("free for a month") — the form that dodges a digit grep, and precisely how the original survived. SKIPS with no config; **FAILS when the config matches no files**, because an assertion that has stopped looking at anything must not read as green. First run against the real repo: **7 findings, zero false positives** — all three defects fixed that day would have been caught on day one, plus a supplier page advertising "$99"/"$499" tiers and "First 2 months free" against live Stripe prices of $199/$299. 15 tests, mutation-verified. |
